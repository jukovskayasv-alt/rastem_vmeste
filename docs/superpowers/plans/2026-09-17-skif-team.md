# SKIF Team Implementation Plan

> **For agentic workers:** Use focused parallel implementation for independent finance and document modules; integrate and verify locally before delivery.

**Goal:** Build an owner-controlled four-role Telegram prototype with shared SKIF facts, calculations, document drafts and presentation review.

**Architecture:** Four Telegram tokens use one Python server. SQLite owns task history and explicit publication state. An optional Responses API adapter produces source-based analysis and visual review.

**Tech Stack:** Python 3.11+, standard-library HTTP/SQLite/unittest, ReportLab, PyMuPDF, python-docx.

**Spec:** `docs/superpowers/specs/2026-09-17-skif-team-design.md`

## Global constraints

No live credentials in the package; no public launch, payment, signature or legal filing. Owner IDs fail closed. All generated agreements are drafts. No unapproved construction/return claims. Existing price correction is authoritative.

### 1. Finance and agreements

- [ ] Test `build_schedule` cent totals, leap days, negative inputs and zero balance; implement Decimal calculations.
- [ ] Export the same schedule to CSV/ICS; never recalculate amounts with a language model.
- [ ] Test contract validation blocks missing cadastral identification; generate explicitly marked DOCX drafts from structured terms.

### 2. Data and Telegram runtime

- [ ] Test authorization and task isolation; implement shared database, saved update offsets, task ownership and handoff.
- [ ] Test publication state transitions: only owner can approve; repeated request is rejected; ambiguous send does not retry.
- [ ] Implement Telegram long polling and file sending through documented Bot API; run offline transport tests.

### 3. Content and quality

- [ ] Add roles, fact provenance and source policies.
- [ ] Add bounded PDF creation/review loop with real project assets, deterministic checks and optional image-based review.
- [ ] Add research/copy draft commands and a source-citation requirement.

### 4. Delivery

- [ ] Run all deterministic tests and offline demonstration.
