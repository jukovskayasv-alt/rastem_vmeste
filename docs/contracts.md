# Расчеты и черновики договоров

Модули создают локальный беспроцентный график и неподписанные проекты договоров для полевых участков ЛПХ. Они проверяют формат и согласованность данных, а не право продавца, достоверность ЕГРН или законность конкретной сделки. Каждый DOCX содержит заметный статус черновика и перечень незаполненных условий для юриста. Подписей, отправки в Росреестр и подтверждения оплаты нет.

## Расчет

```python
from pathlib import Path
from skif_agents.finance import build_schedule, export_schedule

schedule = build_schedule("600000.00", "120000.00", 12, "2026-10-31")
paths = export_schedule(schedule, Path("output/example"))
```

`build_schedule(price: str, down_payment: str, months: int, start_date: str) -> dict` возвращает:

```json
{
  "price": "600000.00",
  "down_payment": "120000.00",
  "months": 12,
  "start_date": "2026-10-31",
  "rows": [
    {"number": 0, "date": "2026-10-31", "amount": "120000.00", "balance": "480000.00"},
    {"number": 1, "date": "2026-11-30", "amount": "40000.00", "balance": "440000.00"}
  ]
}
```

В примере ответа сокращен массив `rows`: действительный результат содержит все 13 строк. Все суммы в рублях, строго с двумя десятичными знаками. Строка 0 — первоначальный взнос в `start_date`, в том числе нулевой. Последующие даты сохраняют исходное число месяца: после 31 января следует 28 или 29 февраля, затем 31 марта. Взнос не включается в число `months`.

- Цена положительная, до `999999999999.99`; взнос от нуля и строго меньше цены.
- Деньги принимаются строками с точкой или запятой, не более двух десятичных знаков. Пробелы по краям удаляются. `NaN`, бесконечность, знак минус, экспонента, разделители тысяч и `float` отклоняются. Даже `1.000` отклоняется без скрытого округления.
- `months` — целое число от 1 до 360, `bool` не допускается. Остаток должен обеспечивать каждый платеж не меньше одной копейки. Схема с полной оплатой в день 0 не является рассрочкой и не принимается.
- Даты строго `YYYY-MM-DD`; несуществующие даты и выход за календарь года 9999 отклоняются.
- Основной ежемесячный платеж — целая часть деления остатка в копейках на число месяцев. Все оставшиеся копейки входят в последний платеж. Сумма равна цене, последний остаток равен нулю.
- Проценты, комиссии, пени, налог и перенос на рабочий день не рассчитываются. Правила срока платежа необходимо проверить в конкретном договоре.

`export_schedule(schedule, directory: Path) -> list[Path]` возвращает `schedule.csv` и `schedule.ics`. CSV имеет UTF-8 BOM и колонки `number,date,amount,balance`. ICS содержит события на целый день, корректные переносы строк CRLF и свертку до 75 байт UTF-8. Будильников, приглашений и импорта в чужой календарь нет. Повторный экспорт того же графика сохраняет UID событий; поведение повторного импорта зависит от приложения календаря. Экспорт заново проверяет график и отвергает ручное изменение платежей. Файлы с этими именами в указанной папке заменяются; используйте отдельную папку для каждой задачи.

## Карточка сделки

`create_contract(kind: str, data: dict, output: Path) -> Path`, где `kind` равен `preliminary` или `main`. Результат — новый `.docx`. Существующий файл не перезаписывается; будет `FileExistsError`. Неверные данные дают `ValueError` до создания файла.

| Поле | Требование |
| --- | --- |
| `cadastral` | Полный номер в формате `AA:BB:CCCCCC:D` или `AA:BB:CCCCCCC:D`; последняя часть от 1 до 10 цифр. Это проверка формата, а не существования участка. |
| `address`, `category`, `vri` | Непустые строки из подтверждающих документов. |
| `area_m2` | Положительная десятичная строка с максимум двумя знаками. |
| `seller_name`, `buyer_name` | Непустые строки; реквизиты и личность человека модуль не придумывает и не проверяет. |
| `price` | Положительная цена всего конкретного участка, десятичная строка. |
| `contract_date` | Дата проекта, `YYYY-MM-DD`. |
| `land_regime` | Только `field_lph`. Другие режимы требуют другого шаблона. |
| `construction_allowed` | Только логическое `false`. Блок о запрете строительства нельзя выключить. |
| `demo` | Необязательное логическое значение; по умолчанию `false`. При `true` разрешен только `cadastral="DEMO-ONLY"`. |
| `deadline` | Для `preliminary`: последний день заключения основного договора, позже `contract_date`. |
| `transfer_days` | Для `main`: целое число 1–365. В этом проекте срок передачи отсчитывается после регистрации перехода права; условие должен согласовать юрист. |
| `payment_method` | Для `main`: непустое описание способа расчетов. |
| `payment_due_date` | Для `main` без рассрочки: явная дата единовременной оплаты не раньше `contract_date`. |
| `installment` | Необязательный объект строго с `down_payment`, `months`, `start_date`. Цена берется только из `price` карточки. |

Текстовые поля ограничены 2000 символами; управляющие символы запрещены. Поле `verified` не предоставляет юридического одобрения: такой механизм в модуле отсутствует. Даже полностью заполненная карточка дает только черновик.

При рассрочке для основного договора `start_date` не может быть раньше `contract_date`. Для предварительного договора первая дата графика должна быть не раньше `deadline`: это ограничение текущего шаблона, позволяющее не создавать платежи до предусмотренного срока заключения основного договора. График в предварительном договоре — предложение условий будущего основного договора. Аванс, задаток и обязанность платить до него не создаются. `interest_rate`, другая цена и любые дополнительные ключи внутри `installment` отклоняются.

```python
import json
from pathlib import Path
from skif_agents.contracts import create_contract

data = json.loads(Path("data/deal.example.json").read_text(encoding="utf-8"))
create_contract("preliminary", data, Path("output/preliminary.docx"))
create_contract("main", data, Path("output/main.docx"))
```

`data/deal.example.json` содержит вымышленные стороны, адрес и обозначение `DEMO-ONLY`. Учебная цена 600 000 рублей не связывается с реальным кадастровым номером, в том числе с номером, заканчивающимся на `:2371`. Паспортных данных и банковских реквизитов в примере нет. Для реальной карточки сведения проверяет ответственный специалист; чувствительные реквизиты добавляются защищенным способом вне Telegram.

## Что проверяет юрист

До подписания нужны актуальная выписка ЕГРН и документы основания права, границы и площадь, ограничения и права третьих лиц, семейный статус и нужные согласия, полномочия сторон и представителей, нотариальная форма при ее обязательности и специальные правила оборота конкретной земли. Отдельно согласуются приемка, регистрация, расчетный механизм, реквизиты, просрочка, залог при рассрочке и его снятие, последствия отказа или приостановления регистрации. Незаполненные места в проекте явно помечены. Строительство на полевом ЛПХ сейчас запрещено; планы изменения режима не равны разрешению.

## Проверка

```bash
python -m unittest discover -s tests -p 'test_finance.py' -v
python -m unittest discover -s tests -p 'test_contracts.py' -v
```

Тесты проверяют точность сумм, конец месяца, високосный год, границы входных значений, UTF-8 ICS, защиту от изменения платежей, отсутствие существенных полей, разделение демонстрации и реальной карточки, содержимое графика в DOCX и защиту существующего файла. Их прохождение не заменяет визуальную проверку сформированного DOCX и юридическую проверку сделки.
