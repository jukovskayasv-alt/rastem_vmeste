# СКИФ — команда ИИ-помощников в Telegram

**Версия 0.2, 17.09.2026. Статус: программный пилот с подготовленным обновлением через GitHub. На существующем сервере приложение ещё не установлено и не проверено.**

Владелец уже зарегистрировала `@Skif_Gorshkova_Finance_bot` и заменила ранее раскрытый токен. Три остальные роли и действующие ключи ещё нужно настроить. Токенов в этом репозитории нет.

Главные приоритеты владельца на 17.09.2026: создание пилотной версии проекта СКИФ и уточнение ПЗЗ / возможности получения ГПЗУ по конкретным участкам. Canva исключена. Этот пакет не отправляет обращения в органы власти и не означает согласования застройки.

## Команда

| Роль | Результат |
|---|---|
| Юрист | Разбор режима земли, перечень документов, план дистанционной сделки, вопросы банку/нотариусу, проверка проектов договоров с поиском источников |
| Дизайнер | PDF по шаблону СКИФ, реальные фото, проверка содержания и вёрстки, визуальная проверка моделью и максимум три попытки исправления |
| Расчётчик | Рассрочка без процентов с точностью до копейки, CSV, календарь ICS; проекты предварительного и основного договоров DOCX |
| Аналитик и редактор | Исследование рынка восточного Крыма, сценарии ликвидности и черновики блога Светланы; публикация только точного подтверждённого текста |

Общая база: `data/project.json`. Общие задачи, лиды и состояния публикации сохраняются в SQLite на сервере. Поручение можно передать другому специалисту через `/handoff`. Четыре бота не переписываются друг с другом в Telegram: координацию выполняет сервер.

## Что готово и что ещё не подключено

Готовы обработчики команд, внутренний журнал, расчётчик, календарь, договорные шаблоны, PDF и проверки. Подключения Telegram и ИИ реализованы, но не проверены на действующих аккаунтах — ключей в пакете нет. Доступ разрешается только указанным владельцам в личных чатах.

Не подключены автоматически: Notion, Яндекс Диск, Росреестр, банк, нотариат, электронная подпись, автоматическая отправка клиентам. Плагин Notion в ChatGPT не передаёт авторизацию внешнему Telegram-серверу. Для синхронизации с ним понадобится отдельная интеграция и доступ. Пока общий реестр хранится в этом пакете и обновляется владельцем.

Бот юридической роли — помощник по подготовке материалов. Банковская безопасная сделка, удостоверение, подписание и регистрация выполняются соответствующими участниками, а не ботом. Договорные шаблоны ограничены обычной продажей полевого ЛПХ и не заменяют индивидуальную правовую проверку.

## Обновления через GitHub на существующей ВМ

Целевой репозиторий уже существует: `jukovskayasv-alt/rastem_vmeste`. Сейчас он публичный; подключение имеет право загрузки. Для СКИФ выделена ветка `skif`, где приложение находится в корне, а существующие ветка `main` и сайт остаются без изменений. Загрузка ветки готовится, но её наличие на GitHub и запуск Actions ещё не подтверждены.

До установки self-hosted runner владелец должна открыть **Settings → General → Danger Zone → Change repository visibility** и сделать репозиторий **Private**. Workflow сохраняет дополнительную защиту: production deploy разрешён только для приватного `jukovskayasv-alt/rastem_vmeste`, только при `push` в `skif`. Пароль и токены в чат не передаются.

Порядок первоначальной установки — в [ops/README_RU.md](ops/README_RU.md). Установщик запускается владельцем на уже созданной Ubuntu 24.04 ВМ. Он готовит отдельного пользователя для GitHub Runner; доступ этого пользователя к Docker фактически даёт административные права на выделенный сервер проекта.

После подключения изменения `skif` проходят тесты на GitHub, затем исполнитель `skif` обновляет приложение на ВМ. Изменения в PR проверяются отдельно от рабочего сервера. До остановки текущей версии собирается новый образ и проверяются настройки и доступ к четырём ботам. Неуспешный запуск вызывает попытку возврата предыдущего образа; результат записывается в журнал обновления. Готовность workflow к GitHub CI не означает, что runner установлен или приложение развёрнуто на реальной ВМ.

Для этого способа секреты находятся в `/opt/skif/.env`, рабочая база и результаты — в постоянном Docker volume `skif_runtime`. Справочные `data/` находятся внутри образа и возвращаются вместе с его версией. Откат кода не откатывает рабочую базу; изменение её схемы требует отдельной проверки совместимости. Не запускайте рядом второй экземпляр через Compose с теми же токенами.

Команды приложения `check`, `probe`, `health` различаются: первая проверяет заполнение настроек, вторая — только `getMe`/`getWebhookInfo`, третья — свежий сигнал работы конкретной версии и четырёх ролей. `health` не доказывает качество ответов ИИ. Реальные Docker-сборка, установка на ВМ и Telegram/ИИ-аккаунты пока не проверены; границы локальных проверок указаны в `VERIFICATION.md`.

## Попробовать без ключей и без расходов на ИИ

Требуется Python 3.11 или новее; Docker-образ использует Python 3.12.

```bash
python -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m skif_agents demo
```

Windows: используйте `.venv\Scripts\python.exe` и `.venv\Scripts\pip.exe`.

Каждый запуск сохраняет новый набор в отдельную папку `demo/run-…`, сохраняя предыдущие примеры.

Демонстрация создаёт график 600 000 ₽ / взнос 200 000 ₽ / 12 месяцев, CSV, ICS, два демонстрационных DOCX и PDF. Это пример расчёта, не согласованная рассрочка продавца. В договорных примерах все стороны вымышленные, а кадастровый идентификатор — `DEMO-ONLY`; использовать их для сделки нельзя. Статус PDF `demo_structural_only` означает, что ИИ-проверка изображений не запускалась.

## Отдельный ручной запуск без автоматического обновления

Этот вариант использует `.env` в корне локальной копии приложения. Для утверждённой схемы GitHub → ВМ используйте инструкцию `ops/README_RU.md` и `/opt/skif/.env`.

1. Бот расчётов `@Skif_Gorshkova_Finance_bot` уже зарегистрирован владельцем. В официальном **@BotFather** создайте оставшиеся три роли командой `/newbot`: «СКИФ · Юрист», «СКИФ · Презентации», «СКИФ · Аналитик». Доступность username проверяет Telegram.
2. На вашем постоянном сервере скопируйте `.env.example` в `.env`. Внесите четыре токена. С аккаунта **@Gorshkova_Svetlana** отправьте `/start` боту расчётов, затем выполните `python -m skif_agents identify`: команда покажет числовой ID только по этому входящему сообщению. Внесите ID в `SKIF_OWNER_IDS`. **Токены и ключи не отправляйте в чат.**
3. Добавьте ключ доступного вам API-аккаунта и модель, поддерживающую Responses API, анализ изображений, Structured Outputs и web search. Используйте сервис только в пределах его условий и региональной доступности. API оплачивается отдельно от ChatGPT.
4. Выполните `python -m skif_agents check`. Команда сообщает только названия недостающих настроек, не показывает секреты.
5. Запустите `docker compose up --build -d` либо `python -m skif_agents run` под менеджером процессов. Нужен один экземпляр приложения и постоянный диск для `runtime/`. Сервер не требует входящего публичного порта: используется long polling.
6. Откройте каждого бота и нажмите Start. Проверьте `/project`, `/calc`, `/deck` и вопрос юристу. Сначала используйте только демонстрационные данные.

Не запускайте два экземпляра с одинаковыми токенами. Существующий webhook автоматически не удаляется: остановите прежнее приложение и осознанно переключите способ получения сообщений.

## Примеры поручений

```text
/ask Составь план уточнения ПЗЗ и возможности получения ГПЗУ для 90:07:130301:2371. Отдельно перечисли нужные документы и вопросы администрации.
/deck Короткая презентация для инвестора, светлый фон, реальные фотографии, карта и текущие ограничения.
/calc 600000 200000 12 2026-10-01
/contract preliminary example
/contract main example
/research Какие проверяемые факторы влияют на ликвидность земли рядом с Семёновкой? Отдели цены объявлений от подтверждённых сделок.
/blog Жизнь у моря: спокойствие и открытое пространство. Без выдуманных историй и обещаний строительства.
/lead Анна | контакт согласован с клиентом | участок уточняется | отправить схему
/tasks
/handoff ID legal Проверь формулировки перед показом покупателю
```

Точные поля договоров — `docs/contracts.md`. Для реальной сделки данные передаются в JSON в приватной команде либо генерируются локально по защищённой карточке. Не добавляйте паспортные сканы и банковские секреты. В этой версии долговременные напоминания не отправляются: ICS импортируется в календарь владельца.

## Блог: утверждение точного текста

Оставьте `SKIF_BLOG_CHANNEL` пустым для режима только черновиков. Для публикации укажите свой канал и предоставьте боту аналитика право публиковать.

`/approve ID` показывает полный пост и команду `/publish ID контрольный_код`. Публикуется только этот сохранённый текст. Повторная команда не дублирует пост. Если Telegram не подтвердил ответ, публикация получает статус `unknown`; сначала проверьте канал вручную. Не создавайте повторную публикацию до проверки.

## Как контролируется качество и расход

- Калькулятор, даты, договорные шаблоны и обычные команды выполняются без вызова ИИ.
- Исследование запускается по запросу; постоянный мониторинг не включён.
- В модель передаются текущие относящиеся к задаче факты, а не весь чат.
- Сначала проверяется структура презентации. Визуальная проверка запускается только после успешной сборки PDF.
- Максимум три цикла дизайна. Непройденная проверка возвращает отчёт; система не крутит бесконечную генерацию.
- `SKIF_DAILY_AI_CALLS=40` ограничивает число вызовов за сутки UTC, включая неудачные. Это **не денежный лимит**; финансовые ограничения задайте также у API-провайдера.
- В пилоте дизайнер использует утверждённый каталог текстов. Новые фактические обещания не добавляются автоматически; обновление цены и каталога выполняется совместно. Это ограничение намеренное и отмечено в отчёте.

## Эксплуатация

Сохраняйте резервные копии `runtime/team.sqlite` вместе с SQLite WAL корректным штатным способом, папки результатов и `data/`. Ограничьте доступ к серверу, включите шифрование диска и определите срок хранения персональных данных. Код не выводит токены в ошибки. При перезапуске незавершённая работа получает статус `interrupted`, потенциально отправленный пост — `unknown`; автоматического повтора отправки нет.

Для внешнего отдела продаж с клиентскими чатами нужна следующая итерация: отдельные права сотрудников/клиентов, политика персональных данных, согласованные сценарии ответов и проверка доступа. Текущий пилот — внутренний инструмент владельца.
